# 01. 기획과 데이터 구축

## 들어가며

화학물질을 다루다 보면 "이 물질과 물성은 비슷한데, 덜 위험하고 값도 싼 대체재는 없을까?"라는 질문이 자주 나온다. 이 질문에 데이터로 답해보려는 게 이 프로젝트의 출발점이다. 이 글에는 프로젝트를 어떻게 기획했는지, 첫날(8/15) 데이터를 어떻게 구축했는지, 그리고 데이터셋의 각 컬럼이 무엇을 뜻하는지를 정리했다.

## 1. 프로젝트 기획

### 1.1 주제

화학물질의 물성(Property), 유해성(Hazard), 가격(Price)을 함께 분석해서, 특정 물질에 대해 "물성은 비슷하지만 유해성은 낮고 가격은 합리적인" 대체 물질을 추천하는 시스템을 만드는 것이 목표다.

### 1.2 기존 연구와의 차이

물성과 유해성을 함께 보는 도구는 이미 있다. 그린케미스트리 분야의 용매 선택 도구들이 대표적이다. AstraZeneca/ACS Green Chemistry Institute의 292개 용매 클러스터링 연구, SUSSOL, 최근의 트랜스포머 기반 그린 용매 스크리닝 도구들을 살펴봤는데, 공통적으로 가격은 다루지 않았고 대상도 용매(Solvent)로 한정돼 있었다. 그래서 이 프로젝트는 가격까지 포함하고, 용매에 국한하지 않고 화학물질 전반을 대상으로 잡았다.

### 1.3 우선순위

개인 프로젝트라 시간이 제한적이어서 목표를 두 단계로 나눴다.

1. 물성·유해성 예측 모델 구축 (필수 목표)
2. 대체 물질 추천 시스템 (시간이 남으면 진행)

데이터 확보에만 전체 일정의 60~70%가 들 것으로 예상했기 때문에, 1단계만 끝내도 결과물이 나오도록 설계했다.

### 1.4 전체 파이프라인

SMILES(분자 구조 문자열)를 출발점으로 임베딩 생성, 물성·유해성 예측, 유사도 기반 추천 순으로 설계했다.

| 단계 | 내용 | ML/DL 적용 |
|---|---|---|
| ① 구조 데이터 확보 | CAS 번호로 PubChem API에서 SMILES 확보 | 미적용 |
| ② 데이터 매칭·병합 | InChIKey 기준으로 물성·유해성·가격 데이터 매칭 | 미적용 (규칙 기반) |
| ③ 분자 표현 | RDKit fingerprint 또는 GNN 임베딩 생성 | 적용 |
| ④ 물성 예측 | 실측값이 없는 물질의 물성(끓는점 등) 회귀 | 적용 |
| ⑤ 유해성 예측 | 실측값이 없는 물질의 유해성 분류 | 적용 |
| ⑥ 실측/예측 태깅 | measured/predicted 구분 기록 | 미적용 |
| ⑦ 추천 시스템 | 임베딩 유사도 + 유해성·가격 조건으로 랭킹 | 부분 적용 |

설계 원칙 중 가장 중요하게 둔 건, **실측값이 이미 있는 물질은 예측하지 않고 실측값을 그대로 쓴다**는 것이다. 예측은 실측값이 없는 물질에만 적용한다.

### 1.5 계획했지만 필요 없어진 단계

처음에는 ①단계를 "CAS 번호로 PubChem API에서 SMILES 확보"로 잡았다. 그런데 실제로 받아본 물성 데이터셋(ChemXploreML)과 유해성 데이터셋(MoleculeNet Tox21)에는 이미 SMILES가 들어 있었다. 그래서 이 단계는 빠지고, SMILES에서 바로 InChIKey를 계산하는 것으로 충분했다.

반대로 나중에 가격 데이터를 모을 때는 역방향 변환이 필요해졌다. 가격 사이트(LookChem)가 CAS 번호 기반 URL을 쓰기 때문에, 가지고 있던 InChIKey로 CAS 번호를 찾아야 했다. 이를 위해 물성·유해성 데이터셋의 InChIKey 합집합(14,008개)을 PubChem API에 조회했다.

```
물성 데이터셋(mp, bp)의 InChIKey  ─┐
                                    ├─ 합집합 (고유 InChIKey 14,008개)
유해성 데이터셋(tox21)의 InChIKey ─┘
                ↓
     각 InChIKey를 PubChem API에 조회
                ↓
              CAS 번호 추출
```

PubChem에는 InChIKey로 CAS 번호를 바로 돌려주는 엔드포인트가 없다. 대신 화합물의 동의어(synonym) 목록을 반환하는데, CAS 번호가 다른 이름들과 섞여서 들어 있다.

```python
GET https://pubchem.ncbi.nlm.nih.gov/rest/pug/compound/inchikey/{InChIKey}/synonyms/JSON

# 응답 예시(에탄올): ["ethanol", "ethyl alcohol", "alcohol", "64-17-5", "grain alcohol", "EtOH", ...]
```

이 목록에서 `숫자-숫자-숫자`(예: `64-17-5`) 형식에 맞는 항목을 정규식으로 골라내 CAS 번호를 얻었다.

### 1.6 데이터 확보 계획

- **물성**: CRC Handbook 기반 공개 데이터셋. 녹는점, 끓는점, 증기압, 임계온도, 임계압력 등을 포함한다.
- **유해성**: Tox21. 12개 독성 엔드포인트(핵수용체 신호 7종, 스트레스 반응 5종)에 대한 이진 라벨이다.
- **가격**: 상업 데이터라 공개 데이터셋에는 없고, 공식 API도 기업 계약 전용이라 직접 수집해야 했다. 수집 전에 각 사이트의 robots.txt를 확인하고, 요청 간격을 두어 사이트에 부담을 주지 않는 방식으로 진행하기로 했다. 가격이 없는 물질은 삭제하지 않고 `has_price` 플래그로 표시해서, 모델링에는 그대로 쓰고 추천 단계에서만 필터링하도록 했다.

### 1.7 데이터 매칭 기준

여러 데이터셋을 합치려면 같은 물질인지 판단할 기준이 필요하다. 화합물 이름은 상품명과 IUPAC명, 표기법, 염·수화물 형태 차이 때문에 신뢰하기 어려워서 매칭에 쓰지 않았다.

| 식별자 | 용도 |
|---|---|
| InChIKey | 구조에서 직접 계산되는 해시값. 주 매칭 키 |
| CAS 번호 | 데이터셋마다 표기 형식이 달라 보조 확인용 |
| PubChem CID | PubChem 내부 식별자 |
| 물질명 | 참고용으로만 보관 |

## 2. 첫날(8/15) 진행 내용

### 2.1 데이터 폴더 정리

받아온 물성 데이터 폴더에 json, pdf, pkl, log, html 같은 부산물이 수천 개 있었다. 확인해보니 원 논문(ChemXploreML)의 정제 파이프라인이 남긴 산출물이어서 모두 지우고, 실제 데이터인 csv 7개만 남겼다. 파일명은 출처에 따라 `crc_`(CRC Handbook), `moleculenet_`(MoleculeNet) 접두사를 붙였다.

### 2.2 데이터 출처 확인

물성 데이터셋의 출처를 명확히 해두기 위해 원 논문을 찾아 확인했다. "A Machine Learning Pipeline for Molecular Property Prediction using ChemXploreML"(Journal of Chemical Information and Modeling, 2025)에서 공개한 데이터셋이다. 이 논문도 CRC Handbook의 물성값을 CAS 번호 기반으로 PubChem에서 SMILES와 매칭했는데, 처음 기획한 데이터 확보 방식과 같은 접근이었다.

### 2.3 InChIKey 추가

SMILES를 RDKit `Chem.MolFromSmiles()`로 분자 객체로 바꾸고 `Chem.MolToInchiKey()`로 InChIKey를 계산해, 물성 6종과 유해성 1종 데이터셋 전체에 컬럼을 추가했다. 파싱 성공률은 모든 데이터셋에서 100%였다.

### 2.4 데이터 품질 검증과 정제

첫날 시간을 가장 많이 쓴 부분이다. 각 물성의 `.describe()`를 보다가 녹는점 최댓값이 1340°C로 튀는 걸 발견했고, 원인을 추적해보니 두 가지 문제가 있었다.

1. **무기·이온성 화합물 혼입**: `N#CN.[Ca+2]`(칼슘 시안아미드)처럼 금속 양이온을 포함한 무기염이 유기화합물 물성표에 섞여 있었다. Morgan fingerprint는 공유결합 기반 유기분자를 전제로 한 표현이라 무기염에는 맞지 않는다고 보고 제외했다.
2. **다른 물리량 혼재**: 녹는점 대신 분해온도가 적힌 행(`dec`), 끓는점 대신 승화점이 적힌 행(`subl`), `120-125`나 `>300`처럼 단일값이 아닌 범위·부등호 표기가 섞여 있었다. 원본에서 숫자만 추출하는 과정에서 이 구분이 사라진 것으로 보인다.

전수 검사 결과는 다음과 같다.

| | dec | 금속이온 | subl | 범위 표기 | 제거 후 |
|---|---|---|---|---|---|
| 녹는점 (7,646개) | 468 | 73 | 0 | 107 | 609개 제거, 7,037개 |
| 끓는점 (4,994개) | 113 | 5 | 60 | 23 | 199개 제거, 4,795개 |
| 증기압·임계상수 | 0 | 0 | 0 | 0 | 정제 불필요 |

임계상수와 증기압 데이터에 오염이 없었던 건, 이 값들이 물질이 분해되지 않은 상태에서만 측정 가능하기 때문으로 보인다.

### 2.5 Fingerprint 생성

정제한 녹는점·끓는점 데이터에 InChIKey를 붙여 저장하고, RDKit Morgan Fingerprint(radius=2, 2048비트)를 생성해 세 데이터셋에 적용했다 (`notebooks/03_fingerprint.ipynb`).

| 파일 | 크기 |
|---|---|
| `crc_mp_c_fingerprint.npy` | (7037, 2048) |
| `crc_bp_c_fingerprint.npy` | (4795, 2048) |
| `moleculenet_tox21_fingerprint.npy` | (7831, 2048) |

이것으로 물성 회귀와 유해성 분류 모델에 넣을 입력 피처 준비를 마쳤다.

## 3. 데이터 컬럼 설명

### 3.1 물성 데이터셋

물성 파일 6개는 같은 컬럼 구조를 가진다. 모델링에는 이 중 녹는점과 끓는점을 사용했다.

| 컬럼 | 의미 |
|---|---|
| `INDEX` | 파일 내 순번 |
| `CRC Index` | CRC Handbook 원본 표의 행 번호 (원출처 추적용) |
| `SMILES` | 분자 구조 문자열 |
| `{물성}/{단위}` (예: `tmp/ºC`) | CRC Handbook 원문 값. `31.6(5)`처럼 측정 불확도나 `492 dec`처럼 주석이 붙어 있을 수 있음 |
| `Processed {물성}/{단위}` | 원문에서 숫자만 추출한 값. 모델링에 사용 |
| `InChIKey` | 다른 데이터셋과 매칭할 때 쓰는 27자 식별자 |
| `is_dec` | 원문에 분해(dec) 표기가 있었는지 여부 (녹는점·끓는점만) |
| `is_inorganic_salt` | SMILES에 금속 양이온이 포함됐는지 여부 (녹는점·끓는점만) |

| 파일 | 물성 | 설명 |
|---|---|---|
| `crc_mp_c.csv` | 녹는점 | 결정 구조(packing)의 영향을 받아 2D 구조만으로는 예측이 상대적으로 어렵다 |
| `crc_bp_c.csv` | 끓는점 | 분자간 힘과 직접 연관돼 구조 기반 예측이 비교적 잘 된다 |
| `crc_pc_mpa.csv` | 임계압력 | 임계점에서의 압력 |
| `crc_tc_k.csv` | 임계온도 | 임계점에서의 온도 |
| `crc_vc_cm3mol_raw.csv` | 임계부피 | 임계점에서 1몰이 차지하는 부피 |
| `crc_vp_kpa_25c_filtered.csv` | 증기압(25°C) | 휘발성 지표 |

### 3.2 유해성 데이터셋 (Tox21)

| 컬럼 | 의미 |
|---|---|
| `NR-AR` | 안드로겐 수용체 결합·활성화 |
| `NR-AR-LBD` | 안드로겐 수용체 리간드결합영역 |
| `NR-AhR` | 방향족탄화수소 수용체 (다이옥신류 등 독성물질 대사 관련) |
| `NR-Aromatase` | 아로마타제 효소 저해 |
| `NR-ER` | 에스트로겐 수용체 결합·활성화 |
| `NR-ER-LBD` | 에스트로겐 수용체 리간드결합영역 |
| `NR-PPAR-gamma` | 지질·포도당 대사 관련 수용체 |
| `SR-ARE` | 항산화 반응 경로 (산화 스트레스) |
| `SR-ATAD5` | DNA 손상 반응 (유전독성) |
| `SR-HSE` | 열충격 반응 (일반 세포 스트레스) |
| `SR-MMP` | 미토콘드리아 막전위 붕괴 (미토콘드리아 독성) |
| `SR-p53` | p53 종양억제 경로 활성화 |

`NR-*`는 핵수용체 계열 7종, `SR-*`는 스트레스 반응 계열 5종이다. 값은 0(비활성), 1(활성), 결측 중 하나다. 결측은 고처리량 스크리닝 특성상 물질과 어세이 조합마다 실측 여부가 달라서 생기는 것이라, 오류로 보지 않고 태스크별로 결측을 제외하고 학습했다.

## 마무리

기획 단계에서 정한 원칙(이름 대신 InChIKey로 매칭, 실측값 우선, 물성·유해성 모델 먼저)이 실제 데이터를 다루면서 왜 필요한지 확인할 수 있었다. 무기염 혼입이나 dec·subl 표기 혼재 같은 품질 문제는 기획 단계에서는 예상하지 못한 부분이었고, 데이터를 직접 열어봐야 알 수 있는 문제였다.
